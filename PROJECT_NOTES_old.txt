1. PROJECT GOAL
────────────────────────────────────────────────────────────────────────────────

Build a complete pipeline to:
  (a) Detect and map water bodies from satellite imagery using ML
  (b) Monitor how water body area changes over time (temporal analysis)
  (c) Monitor water quality changes over time
  (d) Present results in an interactive web dashboard

The final dashboard will allow users to:
  - Select a geometry (area of interest) on a map
  - Select a time frame (year range)
  - See water body area increase/decrease over time
  - See water quality changes over time (turbidity, chlorophyll, clarity)

3.1 ENSEMBLE ML MODEL  (water_classification_ensemble.py)
──────────────────────────────────────────────────────────
Class: WaterMaskEnsemble
Approach: Point-based classification (not spatial/patch-based)

X features (8 per pixel — MNDWI added during this project):
  0: B2 (Blue)
  1: B3 (Green)
  2: B4 (Red)
  3: B8 (NIR)
  4: B11 (SWIR)
  5: S1_VV_ASC
  6: S1_VV_DESC
  7: MNDWI = (B3 - B11) / (B3 + B11)

Y label: 1 = water, 0 = non-water

Training samples:
  Water samples    : extracted from annual ground truth shapefiles (~50/year)
  Non-water samples: pixels where MNDWI < threshold, buffered away from water

Models combined (soft voting — probability averaging):
  Random Forest : n_estimators=200, max_depth=20, class_weight='balanced'
  SVM           : kernel='rbf', C=10, probability=True + StandardScaler
  XGBoost       : max_depth=7, lr=0.1, n_estimators=200

Outputs saved to: results_ensemble/
  ensemble_models/rf_model.pkl
  ensemble_models/svm_model.pkl
  ensemble_models/scaler.pkl
  ensemble_models/xgb_model.json
  water_mask_ensemble_{year}.tif
  confusion_matrix_ensemble.png
  feature_importance_ensemble.png

NOTE: MNDWI was added to X features during this project session for all four
      model files (ensemble, rf, svm, xgboost).

3.2 INDIVIDUAL MODEL FILES
───────────────────────────

3.3 U-NET MODEL  (water_classification_unet.py)
────────────────────────────────────────────────
Approach: Patch-based semantic segmentation

Architecture: Standard U-Net
  Input  : (7, 256, 256) — 7-band satellite patch (MNDWI excluded from X)
  Output : (1, 256, 256) — water probability map (sigmoid applied at inference)
  Encoder: 4 blocks (DoubleConv + MaxPool), features = [64, 128, 256, 512]
  Decoder: 4 blocks (ConvTranspose + skip connections + DoubleConv)
  Total parameters: 31,039,937

X features: B2, B3, B4, B8, B11, S1_VV_ASC, S1_VV_DESC (7 bands)
  NOTE: MNDWI is deliberately EXCLUDED from X to avoid label leakage
        (Y is derived from MNDWI, so including MNDWI in X would be circular)

Y labels: Binary water mask derived from MNDWI > 0.0 threshold
  This is a self-supervised labelling strategy — no manual annotation needed.
  Called "pseudo-labels" in remote sensing literature.

Patch generation:
  Patch size : 256 × 256 pixels
  Stride     : 128 pixels (50% overlap)
  Per image  : ~1,890 patches
  Train total: 11,340 patches (2017–2022)
  Test total : 5,670 patches (2023–2025)
  Saved as   : GeoTIFF with proper georeference preserved per patch

  Directory structure:
    D:\rfWater\patches\
      train\
        images\  patch_{year}_r{row}_c{col}.tif   (float32, 7 bands)
        masks\   mask_{year}_r{row}_c{col}.tif    (uint8, 1 band, binary)
      test\
        images\  ...
        masks\   ...

  IMPORTANT: Patches are generated ONCE and reused. The script checks if
             patches already exist before regenerating. To force regeneration,
             delete the patches/ folder.

Pair matching: mask filename = image filename with 'patch_' replaced by 'mask_'
  e.g. patch_2017_r0_c128.tif ↔ mask_2017_r0_c128.tif

Loss function: DiceBCELoss (combined Dice + BCEWithLogitsLoss)
  BCEWithLogitsLoss is used instead of BCELoss for numerical stability.
  Model outputs raw logits; sigmoid is applied during evaluation and inference.

Training config (current quick-test values — change for full run):
  BATCH_SIZE        = 8
  LEARNING_RATE     = 1e-4
  NUM_EPOCHS        = 10
  BATCHES_PER_EPOCH = 80    (set to None for full training)
  BATCHES_PER_EVAL  = 40    (set to None for full evaluation)

GPU setup:
  Device: NVIDIA GeForce RTX 4050 Laptop GPU (6.4 GB VRAM)
  CUDA  : 13.2 (driver), PyTorch CUDA 12.4 wheels used (backward compatible)
  AMP   : Automatic Mixed Precision enabled via torch.amp.autocast('cuda')
          and torch.amp.GradScaler('cuda')
  cudnn.benchmark = True (auto-tunes kernels for fixed 256×256 input)

Model saving: Best model saved as results_unet/unet_best.pth
  Saved whenever test IoU improves during training.
  Prediction step explicitly loads unet_best.pth (not last epoch weights).

Full image prediction:
  Processes scene in 256×256 patches with 128 stride.
  Overlapping patch predictions are AVERAGED for smooth boundaries.
  Outputs:
    results_unet/probability_map_unet_{year}.tif
    results_unet/water_mask_unet_{year}.tif

4. KEY DISCUSSIONS AND DECISIONS
────────────────────────────────────────────────────────────────────────────────

4.1 WHY MNDWI WAS ADDED TO X FEATURES (Ensemble/RF/SVM/XGBoost)
──────────────────────────────────────────────────────────────────
MNDWI = (B3 - B11) / (B3 + B11)
Previously only used internally to generate non-water training samples.
Added as input feature (index 7) to all four classical ML models.
NOT added to U-Net X features — see section 4.2.

4.2 WHY MNDWI IS EXCLUDED FROM U-NET X FEATURES
──────────────────────────────────────────────────
U-Net Y labels are derived from MNDWI threshold (MNDWI > 0.0 = water).
B3 and B11 (used to compute MNDWI) are already in X.
Including the pre-computed MNDWI in X would create direct data leakage —
the model could trivially solve the task by thresholding the MNDWI channel,
learning nothing spatially useful.
U-Net must learn water from raw spectral + radar signals.

4.3 CAN U-NET BE USED WITH THIS DATASET? (discussed before building)
──────────────────────────────────────────────────────────────────────
Dataset limitations for U-Net:
  - Ground truth is point-based (shapefiles), not pixel-level masks
  - U-Net needs dense pixel-level labels

Solution adopted: MNDWI-derived pseudo-labels
  - Apply MNDWI threshold to get binary water mask for every pixel
  - Use this as Y for U-Net training
  - Valid self-supervised approach used in published remote sensing research
  - U-Net adds value over raw MNDWI by learning spatial context, shapes,
    and using S1 radar to correct MNDWI errors (e.g. cloud shadows)

4.4 WHY PATCHES ARE SAVED AS TIF (not NPY)
────────────────────────────────────────────
TIF preserves georeference (transform + CRS) per patch.
This means every patch knows exactly where it is on Earth.
Enables: spatial queries, map overlays, proper geographic analysis.
NPY would lose all geographic information.

4.5 WHY PROBABILITY MAP AND WATER MASK LOOK IDENTICAL
───────────────────────────────────────────────────────
The model outputs values close to 0.0 or 1.0 (not gradients like 0.3–0.6).
This is expected because:
  - Training labels are hard binary (0 or 1 from MNDWI threshold)
  - Water is spectrally very distinct from land — model is confident
Thresholding at 0.5 barely changes the image.
The probability map is useful at pixel boundaries (shorelines) where
the model has intermediate confidence, visible only when zoomed in.

4.6 S1 AND S2 SPATIAL ALIGNMENT IN PATCHES
────────────────────────────────────────────
S1 images have different native resolution and CRS than S2.
In load_sentinel_data(), S1 is reprojected onto the S2 grid using
rasterio.warp.reproject() before stacking.
After stacking, all_bands shape is (7, H, W) — every pixel at every
band index corresponds to the exact same ground location.
Patches extracted at any (row, col) window are spatially consistent
across all 7 bands.

4.7 DATASET CRITICAL CLARIFICATION
─────────────────────────────────────
Each year's data is from a DIFFERENT geographic location.
This means:
  CANNOT DO:
    - Temporal change of one water body over time
    - Multi-temporal U-Net (stacking years is meaningless)
    - Water frequency maps (pixel positions don't correspond across years)
  CAN DO:
    - General water detection model (diverse locations = better generalisation)
    - Cross-location comparison of water body characteristics
    - Per-location water quality analysis

  TO DO TEMPORAL ANALYSIS:
    Re-download data from GEE for the SAME location across all years.
    See section 5 (New Data Download Plan).

  4. Click Run — map preview appears for 2023
  5. Go to Tasks tab → click RUN on each export task
  6. Files saved to Google Drive folder 'rfWater_new'

Bands downloaded (expanded from original 5):
  Sentinel-2 (10 bands):
    B2  (Blue)       — water clarity, CDOM
    B3  (Green)      — MNDWI numerator, chlorophyll proxy
    B4  (Red)        — NDTI turbidity, NDCI denominator
    B5  (Red Edge 1) — NDCI numerator (chlorophyll-a) ← NEW
    B6  (Red Edge 2) — phycocyanin / cyanobacteria    ← NEW
    B7  (Red Edge 3) — chlorophyll supplement          ← NEW
    B8  (NIR)        — NDWI, water/vegetation boundary
    B8A (Narrow NIR) — refined water edge detection    ← NEW
    B11 (SWIR-1)     — MNDWI denominator, turbidity
    B12 (SWIR-2)     — additional turbidity index      ← NEW
  Sentinel-1:
    VV Ascending
    VV Descending

Water quality indices computable from new bands:
  MNDWI      : (B3-B11)/(B3+B11)    — water extent
  NDTI       : (B4-B3)/(B4+B3)      — turbidity
  NDCI       : (B5-B4)/(B5+B4)      — chlorophyll-a concentration
  Clarity    : B2/B4                 — water transparency
  Algae index: B8-B4                 — floating algae / surface vegetation
  Sediment   : B4 mean               — suspended sediment load
  Phycocyanin: B6/B5                 — cyanobacteria (blue-green algae)

NOTE: After downloading new data, update load_sentinel_data() in Python
      scripts to reflect the new band count (10 instead of 5 for S2).
      Band indices will shift accordingly.

6. TIME SERIES PLAN
────────────────────────────────────────────────────────────────────────────────

PREREQUISITE: New data from GEE (same location, all years) — see section 5.

6.1 WATER BODY AREA CHANGE
───────────────────────────
  - Run U-Net prediction on all 9 years (same location)
  - Count water pixels per year → multiply by pixel area (10m × 10m = 100m²)
  - Convert to km²
  - Plot annual water area as time series
  - Compute year-over-year % change

6.2 CHANGE DETECTION MAP (per year pair)
──────────────────────────────────────────
  Compare water mask of year N vs year N-1:
    Pixel value 1 in both  → Stable water (blue)
    Pixel value 0→1        → Water gain (green)
    Pixel value 1→0        → Water loss (red)
    Pixel value 0 in both  → Stable non-water (dark)

6.3 WATER QUALITY TIME SERIES
───────────────────────────────
  For each year, compute indices ONLY within water pixels (mask applied first).
  Then take spatial mean → one value per year per index.
  Plot as multi-line time series chart.

6.4 MULTI-TEMPORAL U-NET (future improvement)
───────────────────────────────────────────────
  Stack T consecutive years as input: shape (T×7, 256, 256)
  For T=3: channels 0–6 = year N-2, channels 7–13 = year N-1,
           channels 14–20 = year N
  U-Net architecture unchanged — only in_channels changes from 7 to T×7.
  Model learns temporal patterns (seasonal wetlands, permanent lakes, etc.)
  Requires: same location data across years (new GEE download).

7. DASHBOARD PLAN
────────────────────────────────────────────────────────────────────────────────

7.1 ARCHITECTURE DECISION
───────────────────────────
WRONG approach (too slow for free hosting):
  User draws geometry → GEE fetches data → U-Net runs → results shown
  Problem: 15–25 minutes per request, free servers time out in 10–30 seconds.

CORRECT approach (precompute offline, serve online):
  OFFLINE (your machine, run once):
    GEE API → download imagery → U-Net → water masks + quality indices
    → save as GeoTIFF + summary CSV
  ONLINE (the website):
    Reads precomputed files, clips to user geometry, serves charts
    No ML at runtime, no GEE calls at runtime → fast (milliseconds)

7.2 TECHNOLOGY STACK
──────────────────────
  Data processing : Python + rasterio + numpy (already in pipeline)
  Backend API     : FastAPI (lightweight, async, JSON-native)
  Dashboard       : Plotly Dash + dash-leaflet (Python-native, map drawing)
  Charts          : Plotly (interactive time series, hover tooltips)
  Raster serving  : Cloud Optimised GeoTIFF (COG) or PNG tiles
  Storage         : Local GeoTIFFs + CSV (or Cloudflare R2 / Backblaze B2
                    for free cloud object storage)

7.3 HOSTING
────────────
  Vercel  : NOT suitable (50MB package limit, 10s timeout, no PyTorch)
  Netlify : NOT suitable (same reasons as Vercel)

  RECOMMENDED: Hugging Face Spaces (free)
    - Built for ML-backed data science apps
    - Supports Python, Gradio, Streamlit
    - No timeout issues for data science workloads
    - Free GPU available for demos

  ALTERNATIVE: Streamlit Cloud (free)
    - Best if using Streamlit as frontend
    - Python-native, easy deployment from GitHub
